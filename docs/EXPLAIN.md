# 課堂口頭說明筆記

## 一分鐘介紹

中醫處方實驗室讓中醫師查相同證型的病例、研究助理統計證型與方劑、學生透過修改 SQL 學習關聯查詢。資料以一次門診病例為中心，連接症狀、證型、方劑與藥材；48 筆教學病例提供固定、可重現的查詢結果。

## 為什麼是九張表？

五張實體或字典表是病例、證型、症狀、方劑、藥材。四張中介表分別處理病例與證型、病例與症狀、病例與方劑、方劑與藥材的多對多關係。

若把所有藥材寫在同一個逗號字串中，就不容易用 JOIN 查詢，還會重複儲存名稱。拆成字典與中介表後，名稱只存一次；主鍵唯一識別資料，外來鍵確保每個關聯都有對應的實體。

`case_syndrome` 的角色屬於關聯：肝鬱脾虛在一個病例可為主證，在另一個病例可為次證。複合主鍵阻止重複關聯，部分唯一索引限制每例至多一個主證。每例「恰有」一個主證由種子驗證確認；唯一索引負責限制至多一筆。

## 三個必須說清楚的資料語意

1. **症狀的三種狀態**：present = 有症狀、absent = 明確否認、沒有關聯列 = 未記載。未記載表示觀察資料待補，absent 表示明確陰性。
2. **病例數與關聯列數**：48 個病例各有一個主證，另加六個次證，因此 JOIN 後有 54 列，但仍是 48 個病例。
3. **零與 NULL**：未使用方劑仍有方劑資料列；LEFT JOIN 在右表沒有配對時補上 NULL。COUNT(右表欄位) 忽略 NULL，COUNT(*) 仍計入這個空配對列。

## 網站如何執行 SQL？

sql.js 將 SQLite 編譯成 WebAssembly，在瀏覽器的 Web Worker 執行 SQL。基準答案和修改答案都在同一份固定種子上實際執行；這讓同學改錯 SQL 後，下一次仍可重現原本的答案。

資料表欄位與草稿可以看、可以改 SQL，但來源資料每次都重新建立。超時查詢由主執行緒終止 Worker，避免整個畫面被遞迴 SQL 卡住。
